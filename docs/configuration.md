# Configuration

This page lists every setting the backend reads, which external provider each
one enables, and what happens when it is left unset.

## How settings load

- Backend settings live in `backend/src/podex/config.py`. The `Settings` model
  reads environment variables with the `PODEX_` prefix. Nested groups use a
  double underscore: `PODEX_<GROUP>__<FIELD>`, for example
  `PODEX_DATABASE__URL`. A single underscore in place of the double one is not
  recognized.
- `Settings` also reads a `.env` file from the process working directory, and
  ignores unknown variables.
- [`.env.example`](../.env.example) at the repository root is the inventory of
  every `PODEX_*` variable with a local development value; these match the code
  defaults except `PODEX_OBSERVABILITY__SENTRY_ENVIRONMENT`, which defaults to
  `production` in code. Copy it to `backend/.env` for local overrides.
- `backend/tests/test_env_example.py` fails when a `Settings` field is missing
  from `.env.example` or from this page, or when either names a variable that
  `Settings` does not define.
- A few providers read their own environment variables outside `Settings`; they
  are listed under
  [Read outside the settings model](#read-outside-the-settings-model).

## Providers

"Unset" means the variable is absent from both the process environment and the
`.env` file in the working directory; the code default then applies. An
explicitly empty value does not generally select the default:

- empty numeric, boolean and list values fail when settings load, so the API and
  the scheduler do not start;
- an empty `PODEX_DATABASE__URL` passes validation but stops start-up and
  migrations, because SQLAlchemy cannot parse it;
- the optional credential and provider strings in the table below treat an empty
  value as not configured, exactly as described in each row; this is why
  `.env.example` can leave them empty.

## Read outside the settings model

This table covers application and provider variables. Variables that only
configure the container images and toolchains are listed under
[Container and toolchain variables](#container-and-toolchain-variables).

| Variable                                     | Read by                                                         | Effect                                                                                                          |
| -------------------------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET` | `backend/src/podex/services/discovery_spotify.py` (`os.getenv`) | See Spotify discovery above.                                                                                    |
| `ANTHROPIC_API_KEY`                          | The Anthropic SDK client                                        | See Anthropic above.                                                                                            |
| `AUTO_MIGRATE`                               | `backend/scripts/start.sh` (container entrypoint)               | `1`, `true`, `TRUE` or `True` runs `alembic upgrade head` before the command; otherwise migrations are skipped. |
| `PUBLIC_API_URL`                             | `frontend/src/lib/config.ts`                                    | Backend API base URL; defaults to `http://localhost:8000/api/v2`. Baked in at build time.                       |
| `PUBLIC_SITE_URL`                            | `frontend/src/lib/site.ts`                                      | Canonical site origin; defaults to `http://localhost:4321`.                                                     |
| `PUBLIC_SENTRY_DSN`                          | `frontend/src/lib/config.ts`                                    | Browser error tracking; disabled when unset or blank.                                                           |

### Container and toolchain variables

The Dockerfiles set these with `ENV`; they configure the build tools and
runtimes, not Podex itself.

| Variable                            | Set in                                                 | Effect                                                                                               |
| ----------------------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| `UV_COMPILE_BYTECODE=1`             | `backend/Dockerfile`, builder stage                    | `uv sync` compiles installed packages to bytecode.                                                   |
| `UV_LINK_MODE=copy`                 | `backend/Dockerfile`, builder stage                    | `uv` copies packages from its cache instead of linking them.                                         |
| `UV_PROJECT_ENVIRONMENT=/app/.venv` | `backend/Dockerfile`, builder stage                    | Location of the project virtual environment that the runtime stage copies.                           |
| `UV_PYTHON_DOWNLOADS=never`         | `backend/Dockerfile`, builder stage                    | `uv` uses the image's Python and never downloads one.                                                |
| `PYTHONDONTWRITEBYTECODE=1`         | `backend/Dockerfile`, both stages                      | Python does not write `.pyc` files at run time.                                                      |
| `PYTHONUNBUFFERED=1`                | `backend/Dockerfile`, both stages                      | Unbuffered stdout and stderr, so logs appear immediately.                                            |
| `PATH`                              | `backend/Dockerfile`, runtime stage                    | Puts `/app/.venv/bin` first, so `uvicorn`, `alembic` and `python` come from the virtual environment. |
| `PODEX_DATABASE__URL`               | `backend/Dockerfile`, runtime stage                    | Sets the code default, `sqlite:///./podex.db`, explicitly; override it at run time.                  |
| `PUBLIC_API_URL`                    | `frontend/Dockerfile`, builder stage (`ARG` and `ENV`) | Baked into the bundle at build time; see above.                                                      |
| `ASTRO_TELEMETRY_DISABLED=1`        | `frontend/Dockerfile`, builder stage                   | Turns off Astro's anonymous telemetry during the build.                                              |
| `NODE_ENV=production`               | `frontend/Dockerfile`, both stages                     | Production mode for the build tools and the Node server.                                             |
| `HOST=0.0.0.0`                      | `frontend/Dockerfile`, runtime stage                   | Address the standalone Astro Node server listens on.                                                 |
| `PORT=4321`                         | `frontend/Dockerfile`, runtime stage                   | Port the standalone Astro Node server listens on.                                                    |

Inputs for the CI scripts and the container smoke tests, such as `IMAGE` and
`PLATFORM`, are documented in
[`.github/scripts/README.md`](../.github/scripts/README.md).

## Pipeline status

The scheduler (`python -m podex.scheduler_runner`) runs episode discovery from
podscripts.co, RSS and Spotify for active podcasts, digest delivery, and
retention sweeps. The enrichment registry, LLM transcript cleanup, LLM mention
extraction and extraction review exist as services but are not called from the
API or the scheduler, and no transcript acquisition provider is implemented.
Their settings above are therefore only exercised by tests today. See
[#59](https://github.com/lgtm-hq/podex/issues/59).
